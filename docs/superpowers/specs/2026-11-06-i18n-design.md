# Interfaccia multilingua (i18n)

Data: 2026-11-06. Stato: approvata dall'utente (Paraglide JS, solo interfaccia).

## Obiettivo

Interfaccia in inglese e italiano, lingua scelta dall'utente e ricordata, e una nuova lingua
aggiungibile senza toccare il codice: un file di messaggi e una riga di configurazione.

## Decisioni

| # | Decisione | Fonte |
|---|---|---|
| I1 | **Paraglide JS 3** (`@inlang/paraglide-js`): compila `messages/{locale}.json` in funzioni tipizzate `m.chiave()`; una chiave inesistente è un errore di TypeScript | Scelta utente 2026-11-06 su inventario (nessuna libreria i18n tra le dipendenze; candidati: Paraglide 3.2, svelte-i18n 4.0.1 fermo al 2024, typesafe-i18n inattivo) |
| I2 | Si traduce **solo l'interfaccia** (testi Svelte, notifiche, errori di validazione del frontend). I nomi Modbus (tabelle, codici funzione, tipi di dato, ordini dei byte) e i testi del backend Rust (descrizioni dei frame, errori di I/O ed eccezioni) restano in inglese, come nella specifica Modbus | Scelta utente 2026-11-06 |
| I3 | Cambio lingua **senza ricaricare la pagina**: un reload chiuderebbe connessioni, poll e simulazioni in corso. `overwriteGetLocale` legge uno `$state` di Svelte, quindi ogni `m.*()` nel markup diventa reattivo; `overwriteSetLocale` aggiorna lo stato e lo salva in `localStorage` | Runtime 3.2.0: i messaggi chiamano `getLocale()` a ogni invocazione (`dist/compiler/runtime/get-locale.js`); `setLocale` ricarica il documento per default (README, "Basics") |
| I4 | Lingua iniziale: quella salvata, altrimenti quella del sistema (`navigator.languages`) se disponibile, altrimenti l'inglese (`baseLocale`) | Comportamento comune delle app desktop |
| I5 | I plugin inlang (`plugin-message-format`, `plugin-m-function-matcher`) sono **dipendenze npm** referenziate con percorso locale in `project.inlang/settings.json`, non URL jsDelivr: build riproducibile dal lockfile, offline, aggiornata da Dependabot | `@inlang/sdk` carica i moduli non-`http` da file (`importLocalPlugins`); misurato: compile e `inlang check` funzionano senza rete |
| I6 | `src/paraglide/` è generata e non versionata. Lo script `npm run i18n` la compila prima di `check` e `deadcode`; `build`, `vitest` e Tauri la compilano tramite il plugin Vite | README di Paraglide ("Never edit `src/paraglide/`") |
| I7 | `inlang check` (`npm run check:i18n`) in CI: fallisce se una lingua non ha tutte le chiavi della lingua base | README di `project.inlang` generato da `init` |
| I8 | Selettore lingua nella barra laterale, sotto il tema; il nome di ogni lingua è il suo autonimo da `Intl.DisplayNames`, così una lingua aggiunta compare senza codice | — |

## Aggiungere una lingua

1. Aggiungere il codice (es. `de`) a `locales` in `project.inlang/settings.json`.
2. Creare `messages/de.json` con tutte le chiavi di `messages/en.json`.
3. `npm run check:i18n` deve passare.

## Cosa NON è dimostrato

- La reattività di `overwriteGetLocale` + `$state` è dedotta dal codice del runtime: va
  misurata nell'app vera (E2E: cambio lingua e testi aggiornati senza reload).
- Paraglide 3.0.0 è uscito il 2026-11-03: versione giovane. Il rischio è limitato dal blocco di
  versione nel lockfile e dai gate di CI.
